# Удалённые и несколько серверов: план

Статус: **этапы 1 и 2 сделаны** (профили, переключатель, сетевая папка по UNC-пути; SFTP через локальное зеркало: `ServerMirror`, `SftpRemote`, `MirrorService`); FTP/FTPS (`FtpRemote`, FluentFTP) тоже сделан: **этап 3 сделан**. Агент на сервере не делаем (решение владельца).

Заметка по реализации: этап 1 обошёлся без слоя `IServerFiles`: профили лишь меняют `ServerPaksFolder`, а код работает с файлами как раньше (UNC-путь работает сам). Для SFTP/FTP проще всего сделать **локальное зеркало** нужных файлов (логи, база, моды) с синхронизацией по сети и записью очереди обратно; тогда весь существующий код остаётся без переписывания.

## Что нужно

- Один пользователь может иметь **несколько серверов** (свой ПК, VPS, выделенный, игровой хостинг), в том числе одновременно.
- Все страницы («Консоль», «Панель», «Сервер», моды, лут) работают с **выбранным сервером**, как сегодня с локальным.
- Доступ к серверу бывает разным, поэтому нужен общий слой «файлы сервера» с разными способами подключения.

## Что нужно приложению от сервера

Всё, что делает приложение, сводится к файлам внутри папки сервера:

| Что | Файлы | Как читается/пишется |
|---|---|---|
| Логи игры | `SCUM\Saved\SaveFiles\Logs\*.log`, `SCUM\Saved\Logs\SCUM.log` | чтение с конца, с запоминанием смещения |
| Данные игроков и машин | `SCUM\Saved\SaveFiles\SCUM.db` (+ `-wal`) | копия целиком (только чтение) |
| Моды | `SCUM\Binaries\Win64\ue4ss\Mods\*`, `mods.txt`, `mods.json` | чтение и запись |
| Мост | `...\Mods\StudioBridge\commands.txt`, `players.txt`, `results.log`, `events.log` | запись очереди, чтение результатов |
| Активность | `...\Mods\StudioActivity\activity.log` | чтение с конца |
| Состояние | запущен ли `SCUMServer.exe` | сейчас по процессу, удалённо нужна замена |

## Способы доступа (провайдеры)

| Провайдер | Для кого | Логи | SCUM.db | Моды и мост | Запущен ли сервер |
|---|---|---|---|---|---|
| **Локальный** | свой ПК | да | да | да | да (процесс) |
| **Сетевая папка** (SMB/диск VPN, `\\host\share`) | своя сеть, VPS через VPN | да | да (медленно) | да | нет: по свежести логов |
| **SFTP/SSH** | VPS, выделенный, Linux-хост с Wine | да | да (кэш) | да | по свежести логов, по желанию командой по SSH |
| **FTP/FTPS** | игровые хостинги с панелью | да | да (кэш) | если хостинг разрешает UE4SS | по свежести логов |
| **API панели хостинга** (Nitrado, G-Portal …) | отдельные хостинги | где даёт API | как правило нет | как правило нет | да |

Решение: делаем **локальный, сетевую папку, SFTP, FTP/FTPS**. API панелей: только если появится явный запрос, у каждого своё.

Оговорка про хостинги: многие не разрешают UE4SS (подмена `dwmapi.dll`). Там будут логи, база и вся «Панель», но не мост, не мод активности и не выдача предметов. Приложение должно это **определять при подключении** и показывать, что доступно.

## Устройство

1. **Слой файлов** `IServerFiles`: `Exists`, `List`, `ReadRange(path, from)`, `ReadAll`, `Write` (через временный файл и переименование), `Append`, `Stat` (размер, время). Реализации: Local, Share (Local по UNC-пути), Sftp (SSH.NET), Ftp (FluentFTP).
2. **Профиль сервера:** имя, тип доступа, адрес, порт, логин, секрет, корневая папка (`...\SCUM Server`), режим (только чтение / с записью). Старая настройка «папка сервера» превращается в профиль «Локальный» при первом запуске.
3. **Секреты** хранятся зашифрованно под учётной записью Windows (как ключ AES). Отпечаток SSH-хоста запоминается при первом подключении и проверяется потом.
4. **Активный сервер** выбирается в шапке/в настройках; страницы получают его слой файлов. Несколько серверов: список профилей, быстрое переключение, позже обзор «все серверы» (онлайн, FPS).
5. **Определение возможностей** при подключении: корень найден, UE4SS есть, можно ли писать в папку модов, есть ли `SCUM.db`, насколько свежи логи.

## Что менять в коде

- `ServerInstall` (сейчас привязан к локальному пути) → описание сервера поверх `IServerFiles`.
- `LogTail`: чтение диапазона через провайдера. Для SFTP это чтение с смещения, для FTP докачка (REST).
- `ServerDashboard`: кэш по размеру и времени файла уже есть, добавить кэш на диск для удалённых.
- `ServerVehicles`: качать `SCUM.db` и `-wal` только при изменении размера или времени, не чаще раза в 30–60 с, хранить копию в кэше приложения.
- `ServerBridge.Enqueue`: записывать новую очередь **целиком через временный файл и переименование** (дописывание по сети ненадёжно, особенно по FTP). Мост на Lua уже умеет забирать файл через `os.rename`.
- `ServerModStore`, `ServerAutoMods`: работают через `IServerFiles`. Для **удалённых серверов автоустановка модов только с явным согласием** (для локального вы просили «всегда»).
- Запущен ли сервер: удалённо определяется по свежести `SCUM.log` или `players.txt` (например, менее 2 минут), для SFTP по желанию командой по SSH.

## Производительность и устойчивость

- Опрос: логи раз в несколько секунд кусками, база раз в минуту при изменении, список игроков как лог. Пауза, когда окно свёрнуто.
- Разрыв связи, таймауты и повторные попытки с нарастающей задержкой; статус «нет связи» в шапке, без блокировки интерфейса (всё в фоне).
- Большие файлы (`SCUM.db` в десятки МБ): только по требованию вкладки «Машины» и по кнопке.
- Тесты: провайдер «в памяти» для всех страниц, реальные SFTP/FTP только опционально (как тесты с данными игры).

## Безопасность

- По умолчанию **только чтение**; запись, отправка команд, установка модов включаются в профиле.
- Никаких паролей в логах и в MCP; ключ AES, как и сейчас, никому не передаётся.
- Мост принимает команды только из своей папки модов, права доступа определяет учётная запись, под которой мы подключаемся (рекомендуется отдельная учётная запись с доступом только к папке сервера).

## Этапы

1. `IServerFiles` и профили, локальный и сетевая папка (миграция старой настройки). **Результат:** всё работает как сегодня плюс несколько профилей и UNC-путь.
2. SFTP (SSH.NET): логи, база, моды, мост. Определение возможностей.
3. FTP/FTPS (FluentFTP) для хостингов, режим «только логи и база» без UE4SS.
4. Обзор нескольких серверов и уведомления.
5. API панелей, если будет запрос.
